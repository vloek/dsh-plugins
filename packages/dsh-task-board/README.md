# dsh-task-board

Доска задач на проверку для DeepSeek Harness. ИИ кладёт задачу (папку с `task.json`, скриншотами и видео), ты в панели **«Задачи»** смотришь доказательства и жмёшь **Принять** или **На доработку** с комментарием. ИИ видит решение: переделывает и отправляет снова или закрывает принятую задачу. **Выполнено** переносит задачу в архив (или удаляет, по настройке).

## Как пользоваться

- **Панель:** левый сайдбар → «Задачи». Слева список задач (вкладки «На доске» / «Архив»), справа выбранная задача. Сверху списка идут те, что ждут проверки, затем принятые, на доработке и в работе. ↑/↓ в списке переключают задачу.
- **Обновление:** панель держит долгий запрос к хосту (`wait`) и перечитывает задачи только когда версия доски изменилась (хост следит за папкой через `fs.watch`; где рекурсивный watch недоступен, он раз в 2 секунды сверяет время изменения папок задач). Если долгий запрос не проходит, панель откатывается на опрос версии раз в несколько секунд. Кнопка «Обновить» в шапке перечитывает принудительно.
- **Подключить ИИ:** кнопка в шапке (и пустая доска) показывает инструкцию: фразу для агента внутри DSH и готовый текст с подставленным путём к доске, который можно скопировать в Claude Code, Cursor, Codex или любой другой ИИ с доступом к файлам.
- **Список:** у каждой задачи слева миниатюра первого скриншота, снизу число скриншотов, видео, файлов и отмеченных критериев.
- **Код:** если в `task.json` есть `branch` и `pr`, на карточке видны ветка и номер PR, а в задаче — ссылка на PR (открывается в браузере) и имя ветки с кнопкой «скопировать».
- **Карточка задачи:** описание (Markdown: заголовки `##` становятся разделами, списки, **жирный**, `код`, блоки кода, цитаты, http(s)-ссылки), чеклист «На что смотреть», галерея скриншотов (клик — во весь экран, стрелки ← →, Esc), видео с перемоткой, текстовые файлы (логи, отчёты) раскрываются прямо в карточке, история. Файлы, изменённые после твоего последнего решения, помечены чипом «новое».
- **Чеклист:** критерии приёмки — чекбоксы. Отмечай, что проверил; отметки хранятся в `task.json` (`checks`), ИИ видит их через `get`. При решении в `review` записывается, что было отмечено и что нет (`review.checked` / `review.unchecked`). Новый раунд (`submit`) начинается с пустыми галочками.
- **Кнопки:**
  - «Принять» — `status: approved`. Ctrl+Enter в поле комментария.
  - «На доработку» — требует комментарий; `status: changes_requested`, комментарий в `review.comment`. Ctrl+Shift+Enter.
  - «Выполнено → в архив» (у принятых) — папка переезжает в `_archive/`.
  - «Удалить» — с подтверждением (второй клик в течение нескольких секунд).
  - «Открыть папку» — показывает папку задачи в файловом менеджере системы (Explorer, Finder, xdg-open).
  - В архиве: «Восстановить на доску», «Удалить навсегда».

## Для ИИ

- **Внутри DSH** — инструмент `task_board` (`list`, `get`, `create`, `update`, `attach`, `submit`, `comment`, `wait`, `complete`) и навык `task-board-format`. `comment` оставляет сообщение проверяющему без смены статуса, `wait` блокируется до твоего решения (или до таймаута, по умолчанию 2 минуты).
- **Снаружи** (Claude Code, Cursor, скрипты) — достаточно писать файлы; формат лежит в `FORMAT.md` в корне доски. Чтобы узнать о решении, не опрашивая task.json, следи за `events.jsonl` в корне: доска дописывает туда строку на каждое действие (решение, галочка, комментарий, закрытие). Есть и HTTP: `rpc` с `action: wait` (долгий опрос по версии доски) и `action: events` (строки после байтового смещения).

```
~/.dsh/task-board/
  FORMAT.md
  events.jsonl
  <task-id>/task.json
  <task-id>/*.png *.mp4 *.log …
  _archive/<task-id>/…
```

## Настройки (`cordis.patch.yml` профиля)

```yaml
- id: task-board
  config:
    root: D:/projects/my-app/.review   # своя папка вместо ~/.dsh/task-board
    onDone: delete                      # archive (по умолчанию) или delete
```

## Устройство

- `lib/store.js` — работа с папками (node:fs, атомарная запись task.json, блокировки на задачу, счётчик версии доски + `fs.watch`, журнал `events.jsonl`, ожидание изменений для долгого опроса).
- `lib/routes.js` — два HTTP-маршрута на соединении DSH: `POST /api/dsh-task-board/rpc` (`version`, `wait`, `events`, `list`, `get`, `check`, `review`, `done`, `restore`, `delete`, `reveal`, `format`) и `GET /api/dsh-task-board/media` (с Range для видео; файлы отдаются с `CSP: sandbox`, текст — как text/plain).
- `lib/index.js` — хост: инструмент, раздел системного промпта, навык, маршруты.
- `lib/text.js` — всё, что плагин говорит модели: описание инструмента, FORMAT.md, рендер задач.
- `lib/client.js` — браузер: панель на React из загрузчика модулей DSH, без сборки.
- `test/run.mjs` — тесты хранилища, маршрутов и текстов: `node test/run.mjs`.
